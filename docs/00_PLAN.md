## 2. 关键设计决策（摘要，详见 02_DESIGN）

1. **不使用原录音，也不演奏原曲主旋律。** 和弦进行本身不受版权保护，但旋律受保护。视频只用和弦进行 + 原创（程序生成）即兴 + 原创伴奏。这也让成品可以安全公开。
2. **音频全部由 MIDI + SoundFont 合成**（GeneralUser GS，开源免费音色库），用 `spessasynth_core`（JS）离线渲染。同一套 MIDI + 音色在浏览器里也能实时播放 —— 视频与网页用**同一个引擎**。
3. **画面用浏览器 Canvas 绘制，再逐帧截取编码成视频。** 渲染函数是纯函数 `render(ctx, t, timeline)`：给定时间 t 就画出那一帧。网页里只需把 t 换成音频的 `currentTime`，就能变成实时互动版本。
4. **所有音乐内容都是 JSON 数据**：和弦表、调性中心、和弦音、每一个独奏音的时间/音高/功能标签（如 `3`、`b9`、`approach`）。视频读它，网页也读它。
5. **配音用离线开源 TTS**（sherpa-onnx + MeloTTS 中英模型），因为本环境无法访问在线语音服务；讲稿与配音文本分离（显示 "Dm7"，读作 "D 小七"）。
6. **颜色编码三颗"星"**：B = 冰蓝、G = 琥珀金、E♭ = 玫瑰红。属和弦继承其目标调的颜色（更暗）。这一套颜色在视频、网页、文档中保持一致。

## 3. 视频结构（目标 ~7.5 分钟）

| 场景 | 内容 | 声音 | 画面核心 |
|---|---|---|---|
| S0 序 | 1959 年，一首让乐手心惊的曲子 | 三个大七和弦的氛围铺底 | 星空 → 标题 |
| S1 背景 | 速度 ~286 BPM、两拍一换、跳远调 | 铺底 | 数字卡片：1959 / 286 BPM / 26 个和弦 |
| S2 常规和声 | 五度圈、ii–V–I、调性"停留" | C 大调 ii–V–I | 五度圈 + 回家的弧线 |
| S3 等分八度 | 12 ÷ 3 = 4，大三度三角形；放回五度圈仍等边 = 最远的三个调 | B、G、E♭ 大七和弦 | 半音圈 → 变形为五度圈，三角形始终等边 |
| S4 引力 | 每个调前放属七：D7→G、B♭7→E♭、F♯7→B | 三组 V–I | 三颗卫星绕三颗星 |
| S5 地图 | 16 小节全貌：前半向下旋转，后半 ii–V 向上 | 乐队慢速（140 BPM）一遍 | 16 格和弦地图 + 圆上跳跃的光点 |
| S6 工具 | 1-2-3-5 音型、三音/七音导音线、半音包围 | 1-2-3-5 示范 | 键盘 + 音名 + 功能标签 |
| S7 慢速即兴 | 程序生成的即兴，140 BPM 两遍 | 次中音萨克斯 + 三重奏 | 钢琴卷帘光带 + 键盘 + 地图 |
| S8 原速 | 回到 ~286 BPM | 同上 | 沉浸式光带与粒子 |
| S9 尾声 | Countdown、26-2；秩序深处才有自由 | 回到 B 大七 | 三角形化为星座，片尾 |

## 4. 执行步骤与顺序

1. 环境探测：ffmpeg ✓、Python ✓、Node ✓、Chromium/Playwright ✓；在线 TTS ✗（被网络策略拦截）→ 改用离线 sherpa-onnx；字体与音色库从 GitHub Releases / git 获取。
2. 文档先行：本计划 + 乐理推导 + 设计 + 数据结构。
3. `music/gs/theory.py` → 生成 `data/giant_steps.json`（单一事实来源）。
4. `music/gs/arrange.py`（贝斯/钢琴/鼓）+ `music/gs/improv.py`（即兴）→ 事件 JSON + MIDI。
5. `audio/render_midi.mjs` → WAV。
6. `music/scripts/build_narration.py` → 逐句 TTS → `build_timeline.py` 用实际配音时长排时间轴 → `timeline.json`。
7. `web/` Canvas 渲染器（可在浏览器里拖动时间预览）→ `video/capture.mjs` 多进程逐帧截取 → ffmpeg 编码 → 混音 → 成品。
8. 抽帧检查画面、检查响度与时长 → 推送仓库、发布视频。

## 5. 风险与对策

| 风险 | 对策 |
|---|---|
| 合成萨克斯不够真实 | 用 GeneralUser GS 的次中音萨克斯 + 力度/表情控制器(CC11)起伏 + 摇摆节奏 + 混响；把重点放在"听清结构"而非拟真 |
| 离线 TTS 读错和弦名 | 讲稿分 `text`（显示）与 `tts`（朗读）两个字段 |
| 逐帧渲染太慢 | 4 进程并行、每进程直接管道送 ffmpeg 分段编码再拼接 |
| 视频文件太大放不进 Git | 视频放 GitHub Release 资产；仓库只放代码与数据，可完全复现 |
