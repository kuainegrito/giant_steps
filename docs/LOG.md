# 工作日志 Work Log

记录制作过程中的思考、决策与踩坑，按时间顺序。日期：2026-10-24。

## 1. 起点：先想清楚"讲什么"

- 这首曲子最常见的讲法是"三个调、大三度"。但只说"大三度"不足以解释它**为什么难**、又**为什么美**。
- 推导时发现一个更有力的视角：B、G、E♭ 在半音圈上是等边三角形（这是定义），**在五度圈上也是等边三角形**（这是结果）。后者说明这三个调在"调性距离"上两两最远（只共享 3 个音阶音）。于是整片的叙事线定为：*最对称的方式，连接最陌生的三个调*。
- 画面上用"半音圈 → 五度圈"的连续变形来证明这一点，成为全片的视觉高潮之一（S3）。

## 2. 版权与内容边界

- 不用原录音、不演奏原曲主旋律。和弦进行不受版权保护，于是视频只用和弦 + 程序生成的即兴。这也恰好契合"讲逻辑"的目的：观众听到的每一个音都能被解释。

## 3. 技术路线的选择

| 问题 | 选项 | 决定 | 理由 |
|---|---|---|---|
| 画面 | Python 绘图 / After Effects 类 / 浏览器 Canvas | Canvas + 无头 Chromium 逐帧截图 | 与未来网页共用代码；`render(t)` 纯函数可并行、可随机访问 |
| 声音 | 自己写合成器 / SoundFont | SoundFont（GeneralUser GS）+ spessasynth_core | 音质远好于自制合成；浏览器端有同一引擎 |
| 配音 | 在线 TTS / 离线 TTS | 离线 sherpa-onnx + MeloTTS 中英模型 | 在线服务被网络策略拦截；离线可复现 |
| 即兴 | 机器学习 / 规则 | 规则 + 加权随机 | 可解释：每个音都有 `cell/degree/role` 标签 |

## 4. 时间轴：让配音驱动一切

- 先合成配音，再按配音实际时长排时间轴，最后才生成背景音乐 —— 这样"念到 G 的时候 Gmaj7 响起"才能精确对齐。
- 第一版是逐分句合成（每个逗号切一段），能直接得到分句时间，但单个字母（"E"、"A"）单独合成时发音很差。
- 改为**整句合成 + 停顿检测**：TTS 在标点处会停顿，取最长的 n−1 段静音作为分句边界。韵律自然多了，时间精度对同步足够。
- 对于"B、C♯、D♯、F♯"这种一个字母一个分句、停顿太短无法可靠检测的情况，改为在整组分句的时间跨度内均匀放置音符。

## 5. 踩坑

1. `spessasynth_core` 写 WAV 默认归一化 → 各段音量失去可比性。改为固定增益 + `normalizeAudio:false`。
2. 序列器默认跳过开头静音 → 以休止开头的即兴整体提前，音画不同步。设 `skipToFirstNoteOn=false`。
3. 第一次抽帧发现"E♭"被渲染成"E ♭"：Cormorant 没有 ♭，回退到思源宋体的全角 ♭。用 `unicode-range` 只为 ♭♯∩ 指定 DejaVu Serif 解决。
4. 圆下方的说明文字与 F♯ 节点标签、字幕重叠 → 说明文字移到右上角。
5. 双行字幕会在词中间断开（"三个降 / 号"）→ 两行时改为在最靠近中点的标点处断行。
6. 乐器平衡：单独渲染各声部比较 RMS，贝斯明显过响、鼓过轻，调整了 MIDI 通道音量；纯伴奏段落（S5）在混音中额外提升。
7. 即兴后处理把音改成半音接近音之后，度数标签没有更新 → 后处理结束后统一重算标签。

## 6. 质量检查

- 每个场景至少抽 1–3 帧拼图检查。
- 用离线 ASR 回测配音（`tools/asr_check.py`）。小 ASR 模型本身对英文字母识别也弱，结论只作参考：中文叙述基本准确，单独的字母音名较含糊（字幕会补足）。
